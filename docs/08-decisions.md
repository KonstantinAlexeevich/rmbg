# 08. Журнал решений и риски

Записи добавляются в конец, старые не переписываются. Если решение отменено — добавляется
новая запись со ссылкой на отменённую.

## Р-01. Интерфейс — отдельная страница-вкладка

Popup закрывается при потере фокуса и ограничен по размеру, side panel узкая. Пакетная
работа с гридом превью, встроенным просмотром «до/после» и панелью настроек требует
полноценной страницы. Иконка расширения открывает вкладку студии (или фокусирует
уже открытую).

Уточнено Р-27: студия — web URL, не `chrome-extension://…/studio.html`.

## Р-02. Модель — isnet-general-use, а не RMBG-1.4

RMBG-1.4/2.0 дают лучшее качество, но лицензированы для некоммерческого использования.
Публичное расширение в Chrome Web Store под это не подходит. `isnet-general-use` под
Apache-2.0, коммерческое использование разрешено, качество на товарной съёмке достаточное.

## Р-04. Два файла весов: fp32 для WebGPU и q8 для WASM

WebGPU-бэкенд ORT не покрывает операторы динамической квантизации, поэтому на q8 значимая
часть графа ушла бы на CPU. fp32 на WASM, наоборот, слишком медленный. Держим оба файла
на хосте, в рантайме качаем ровно один — по фактическому бэкенду (см. Р-16). Цена для
пользователя: 176 МБ или 44 МБ разовой загрузки, а не 220 МБ в пакете.

## Р-05. Ручной фолбэк вместо списка execution providers

`executionProviders: ['webgpu', 'wasm']` скрыл бы факт деградации и оставил бы неподходящий
файл весов. Делаем детект, явный выбор, прогревочный прогон и осознанное пересоздание
сессии при сбое, с уведомлением пользователя.

## Р-06. Хранение в IndexedDB, а не только в памяти

Пачка из 30 фотографий по 12 Мп — это гигабайты в декодированном виде. Блобы уезжают на
диск, в памяти остаются миниатюры. Побочная выгода: сессия переживает закрытие вкладки.

## Р-07. Маска — самостоятельный сохраняемый артефакт

Разделяем дорогую сегментацию и дешёвую композицию. Смена фона, пресета или настроек края
не запускает модель. Это же определяет структуру кода: два независимых модуля.

## Р-08. Cross-origin isolation (COOP/COEP)

Нужна для `SharedArrayBuffer` / ORT. После Р-27 студия на web origin: COOP/COEP задаются
**HTTP-заголовками** Vite `server`/`preview` (и позже reverse-proxy), не ключами манифеста.

Ключи `cross_origin_embedder_policy` / `cross_origin_opener_policy` в manifest
**убраны** из thin package: extension pages (about) isolation не требуют; ORT в ZIP нет.
На web target threads ORT всё равно 1 (Р-27).

## Р-09. Фон в v1 — только прозрачный и однотонный

Градиенты, картинки-подложки и тени откладываем. Модель данных (`background` как
размеченное объединение) позволяет добавить их без миграции.

## Р-10. Пресеты маркетплейсов откладываем, начинаем с произвольного

Требования площадок меняются и требуют проверки; сначала обкатываем механику
пользовательских пресетов. `Preset` уже описан как элемент списка, готовые пресеты добавятся
как предзаполненные записи.

## Р-11. Прогрев фоновый и только на WebGPU

На WebGPU прогрев стоит один форвард-пасс (компиляция шейдеров случилась бы всё равно) и
даёт раннюю проверку операторов. На WASM это полноценный инференс на CPU без выгоды, кроме
раскрутки пула потоков. Поэтому греем только GPU-путь, фоновой задачей при открытии студии,
не блокируя интерфейс.

## Р-12. Letterbox вместо растяжения в квадрат

Референсные реализации (DIS, `rembg`) растягивают кадр в 1024x1024 без сохранения
пропорций. Это искажает геометрию и тонкие детали. Обрезка до квадрата не годится: до
сегментации неизвестно, где объект. Вписываем кадр целиком и добираем поля продолжением
крайних пикселей — пропорции сохранены, ничего не потеряно, ложной границы на стыке нет.
Растяжение как альтернативную реализацию не держим.

## Р-13. Автоматический второй проход по bbox объекта

Если объект занимает меньше половины кадра, на него приходится малая доля входа 1024x1024
и маска грубеет на тонких деталях. Вырезаем bbox с запасом, приводим к квадрату и гоняем
модель повторно уже по нему. Порог включения — площадь bbox меньше 50% кадра при приросте
масштаба не меньше 1.3 раза. Цена — удвоение времени инференса на таких кадрах.

## Р-14. Маска хранится в родном разрешении прохода

Маска, поднятая до размера оригинала, занимает в IndexedDB в разы больше места, а
информации не добавляет: данных в ней всё равно ровно столько, сколько выдала модель.
Храним как есть, вместе с областью покрытия (`coverage`), а разворачиваем на стадии
композиции. Апскейл стоит единицы миллисекунд, зато настройки края применяются к
полноразмерной маске и остаются обратимыми.

## Р-15. Направляемая фильтрация края отложена до v1.1

Апскейл маски с 1024 до полного разрешения даёт интерполированную кромку. Направляемая
фильтрация притянула бы её к настоящим цветовым границам оригинала — линейный по числу
пикселей алгоритм, десятки миллисекунд на 12 Мп, заметный прирост резкости края. Решили
сначала оценить качество без неё: на типичных выводах 1200-1600 px потолок в 1024
маскируется финальным уменьшением, и фильтрация может оказаться незаметной.

## Р-16. Веса скачиваются в рантайме, а не лежат в пакете (отменяет Р-03)

> Часть формулировок про «ORT wasm в пакете расширения» **superseded Р-27**: runtime ORT
> живёт на origin web-студии (`dist-web/ort/`); thin extension ORT не содержит.

Пакет с двумя файлами весов — около 220 МБ. Это качается не только при установке, но и при
каждом обновлении расширения; проверка в Chrome Web Store для такого размера уходит на
ручной разбор и занимает недели. Цена Р-03 — мгновенный офлайн-старт — оказалась ниже
цены тяжёлого пакета.

Веса уезжают на Hugging Face (пин на конкретный коммит). Студия при открытии
определяет бэкенд, понимает, какой из двух файлов нужен, смотрит в кэш и при промахе
качает фоном. Исполняемый ORT / `.wasm` — на origin студии (Р-27), не с CDN как remote
code. `.onnx` — файл данных. Прецедент — Transformers.js + HF.

Цена: состояние «модель ещё не готова» со всеми ветками UI, первый запуск без сети
нерабочий, IP пользователя раскрывается хосту. Это осознанный компромисс.

## Р-17. Кэш в Cache Storage, обязательный SHA-256, список зеркал

Байты весов живут в `caches.open('rmbg-models')`, метаданные — в platform storage
(web: `localStorage`; extension paths: `chrome.storage.local`).
Перед первым использованием обязательна проверка `crypto.subtle.digest('SHA-256', bytes)`
по зафиксированному эталону: мы грузим граф вычислений с чужого сервера, без хэша это
дыра. Зеркало можно не доверять — доверие даёт хэш, а не репутация репозитория. Поэтому
держим список из двух-трёх URL на один и тот же файл; при ошибке сети или несовпадении
хэша пробуем следующее зеркало.

`navigator.storage.persist()` запрашиваем до скачивания: без него Chrome под давлением
диска вычистит кэш, и пользователь снова качает 176 МБ.

## Р-18. Переопределения настроек — слепок на картинку×пресет, а не per-field

Нужна подкрутка layout и края для отдельных кадров без порчи пресета для всей пачки.
Выбран слепок (`ItemOverride`): кнопка копирует текущие значения, дальше они живут в
`ItemRecord.overrides` и не реагируют на правки глобального пресета. Альтернатива —
частичные overrides по полям — даёт неоднозначность «что ещё следует за пресетом» и
усложняет хэш. `output`/`name` в слепок не входят: формат в папке ZIP остаётся
пресетным. Эффективная пара считается через `resolveComposition`.

## Р-19. Просмотр «до/после» в основной области, не модалка

Модалка перекрывала панель настроек — крутить край/layout, глядя на крупный кадр, было
нельзя. Просмотр занимает основную область вместо грида; панель справа остаётся.
Оба кадра слайдера собираются на лету из одного effective preset: при `sizeMode: fixed`
«До» рисуется тем же `layoutSubject`, что и результат, иначе субъект «прыгает». Размер
сцены — через `ResizeObserver`, без CSS-растягивания пропорций.

## Р-20. Действия сессии — в нижней панели, настройки — в боковой

«Скачать всё», «Очистить» и «Добавить файлы» относятся ко всей сессии, а не к пресету,
поэтому живут в нижней панели рядом с прогрессом и счётчиком выбранных. Боковая панель
остаётся только про настройки вывода. Так добавление файлов доступно и при непустом
гриде, а не только на пустом экране.

## Р-21. Боковая панель — край и пресеты в обоих режимах

Сверху «Край маски», ниже — список пресетов. Поля layout раскрываются карандашом
справа от имени активного и показываются сразу под строкой. В просмотре сверху
добавляется шапка картинки: явно сказано, меняют ли правки пресет или только
эту картинку; пресеты переключаются так же, как в гриде. Со слепком поля layout
всегда раскрыты (сворачивать нечего — пользователь как раз их правит).

## Р-22. Терминология UI: профессиональные термины, EN-first

Подписи в интерфейсе — отраслевые термины (Photoshop Select → Modify, Lightroom Export,
Figma), а не описания действий. Расшифровка уходит в тултип. Английский словарь
`locales/studio/en.json` — первоисточник; русский — `locales/studio/ru.json`; runtime —
`src/studio/state/i18n.ts`. Локаль по умолчанию определяется из `navigator.language` с
фолбэком на `en` (переключателя языка нет). Иконки — lucide-react; правило системы:
карандаш = переименование текста, слайдеры = настройки. Глоссарий —
[09-glossary.md](09-glossary.md).

Отменяет принцип из прежней редакции 06-ui.md («подписываем действием, а не термином»).

## Р-23. «Пресет» в UI заменён на Export / «экспорт»

Объект `Preset` ведёт себя не как классический пресет: несколько штук участвуют в
ZIP одновременно, каждая даёт папку, у изображения бывает отклонение (`ItemOverride`).
Сначала пробовали Output / «вариант вывода» — в русском звучит как калька. Итог:
**Export** / «экспорт» (секция Exports / «Экспорты»). Тип и поля в коде (`Preset`,
`presetId`, `exportPresetIds`) не переименовывались. «Формат» не используем из‑за
коллизии с полем Format (PNG/JPEG/WebP).

Открытый вопрос (поведение, не подписи): двойной выбор — активный экспорт отдельно от
галочек «в архив» — после переименования заметнее; естественная модель — в ZIP идут
все, активность значит только «что в превью». Пока не меняем.

## Р-25. Отступ: одно поле + иконка связи, не галка

Четыре поля с галкой «Связать стороны» не читались: неочевидно, что галка относится
ко всем инпутам. Как в Figma: по умолчанию одно значение Padding; иконка Link2 /
Link2Off переключает режим «все стороны одинаково» ↔ «каждая сторона отдельно».

## Р-24. Padding в UI при `fit.margin` в коде

Пространство внутри холста вокруг объекта подписано Padding / «Отступы». Поле в коде
остаётся `fit.margin` до отдельного рефакторинга. Зафиксировано в глоссарии.

## Р-26. Экран About — в web-сборке и (опционально) в extension

Нужны версия, политика и лицензии. About входит в `dist-web` (`about.html`) и по-прежнему
может собираться в пакет расширения. Ссылка «назад» ведёт на URL web-студии, не на
`studio.html` extension origin. Текст политики для дашборда CWS — [cws/privacy.md](cws/privacy.md).

Частично сужает прежнюю формулировку «только extension page как studio.html» — студия
вынесена (Р-27).

## Р-27. Web-студия + thin extension (2026-08)

Цель: хостить студию на домене, из расширения открывать URL; мост «добавить изображение /
сохранить с пресетом» — Р-28.

- отдельная Vite-сборка `dist-web` (`dev:web` / `build:web`), COOP/COEP headers;
- extension `dist` без React/ORT — только SW + CS + about + icons;
- SW открывает `STUDIO_WEB_URL` из `VITE_STUDIO_WEB_URL` (default localhost);
- `src/platform/*` — storage / download / assets / env (`VITE_APP_TARGET`);
- monorepo-пакеты не вводим: один repo, две цели сборки;
- web: `numThreads = 1` — pthread ORT зависает в Vite-dev на nested workers;
- absolute URL для `ort/` — иначе dynamic import в dev ломается.

Не в этом шаге (открыто): popup-экспорт, прод-деплой + `.env.store`,
npm-библиотека studio.

Открытые риски split: listing CWS/`description.md` ещё не продаёт ПКМ; квоты
IndexedDB/Cache — на origin **сайта**, не extension; настройки web не в
`chrome.storage` (в меню уходит только список id/name экспортов — Р-28). Permissions
модель (studio host + optional pool) — закрыта, см. Р-28.

## Р-28. Контекстное меню + studio-only bridge (2026-08)

ПКМ по картинке: «Add to PNG Maker» / «Save without background» (submenu имён экспортов).

- Permissions (модель не пересматриваем при смене домена студии):
  - обязательные: `storage`, `contextMenus`, `activeTab`, `scripting`;
  - `host_permissions` — **только** origin студии из `VITE_STUDIO_WEB_URL` (совпадает с
    `content_scripts.matches`; в `dist/manifest.json` пишет плагин сборки);
  - `optional_host_permissions`: `http://*/*`, `https://*/*` — пул; при ПКМ Chrome
    спрашивает конкретный origin картинки, не весь интернет при установке.
- Extract:
  - `data:` — в SW;
  - `blob:` — inject во вкладке клика;
  - `http(s):` — `permissions.request` на origin картинки **синхронно при клике**
    (до любого `await`), затем `fetch` в SW.
- Job → `chrome.storage.session` → `tabs.sendMessage` → CS → `postMessage` странице.
- Content script `studio-bridge.js` **только** на origin студии; страница синкает
  `{id,name}` экспортов в `chrome.storage.local` для submenu.
- Обработка и скачивание — в web-студии (тот же queue/compose):
  - **Add** — `openStudioTab({ focus: true })`, обычная карточка;
  - **Save** — `focus: false`, item `ephemeral` (не в гриде), compose выбранного
    экспорта, `downloadItem` с `saveAs: false`, затем удаление item.
- Локаль пунктов меню — Chrome `_locales` + `chrome.i18n.getMessage` (язык UI браузера),
  не `settings.ui.locale` студии.
- Permission `downloads` не нужен: save делает web-адаптер студии.

## Риски

- Ревьюер Chrome Web Store может счесть граф `.onnx` логикой (remotely hosted code), а не
  данными. Смягчение: исполняемый код (JS, WASM ORT) с first-party studio origin
  (`dist-web`); в ZIP расширения его нет; `.onnx` — data file + SHA-256; см.
  [cws/submission.md](cws/submission.md).
- CORS через редирект Hugging Face (`resolve` → CDN) — запрос **со страницы студии**,
  не через extension `host_permissions`. Спайк (июль 2026): ACAO есть и на resolve
  (отражение Origin), и на `us.aws.cdn.hf.co` (`*`). Остаточный риск — смена схемы CDN
  или исчезновение ACAO. Смягчение: зеркало / прокси весов на своём origin студии;
  **не** добавлять HF в манифест расширения.
- Вытеснение кэша браузером и повторные 176 МБ. Смягчение: `navigator.storage.persist()`,
  отдельный текст в UI «модель удалена браузером, нужно скачать снова».
- Первый запуск без сети нерабочий. Смягчение: честная ошибка с кнопкой «Повторить», без
  ложных обещаний офлайна до первой загрузки.
- Пиковая память при создании сессии из буфера 176 МБ (буфер в JS-куче плюс копия в куче
  wasm). Смягчение: спайк; при упирании — искать способ отдать ORT поток вместо массива.
- IP пользователя раскрывается хосту Hugging Face при скачивании. Смягчение: один запрос
  за всё время жизни, после него работа офлайн; в политике конфиденциальности явно.
- Совместимость операторов WebGPU. Часть операторов IS-Net может не иметь шейдерной
  реализации в конкретной версии ORT и тихо уйти на CPU. Смягчение: прогревочный прогон
  с замером времени и экран диагностики; при аномально долгом прогоне честно показываем
  «GPU-ускорение неполное».
- Нехватка видеопамяти на слабых GPU при больших изображениях. Смягчение:
  последовательная очередь, освобождение ресурсов после каждой задачи, ретрай на WASM для
  конкретного изображения.
- Отказ Chrome Web Store из-за «remotely hosted code». Для thin package: ORT/JS студии
  с first-party deploy; в ZIP нет бандла воркеров/wasm. Риск остаётся у web-сборки
  (blob:/dynamic worker URL) — проверять `dist-web` до деплоя.
- Расхождение препроцессинга с эталоном. Неверная нормализация даёт «почти работающую»
  маску, которую легко принять за особенность модели.
- Поля letterbox — вход, которого модель не видела при обучении (эталонный конвейер
  растягивает кадр в квадрат). Заполнение продолжением края делает их максимально
  безобидными, но проверить поведение на вытянутых кадрах нужно на реальных фотографиях,
  а не на глаз по одной картинке.
- Квота origin (IndexedDB + Cache Storage). Пользователь с несколькими большими сессиями
  упрётся в лимит, плюс веса делят ту же квоту. Смягчение: `navigator.storage.estimate()`,
  предупреждение, удаление старых сессий.

## Р-29. Студия как installable PWA (2026-08)

Web-студия уже на своём HTTPS/localhost origin (Р-27) — добавляем минимальный PWA-слой,
чтобы пользователь мог «установить» приложение из браузера (standalone окно), без
замены thin extension.

- `public/manifest.webmanifest` + иконки 192/512; link/meta в `src/studio/index.html`.
- Shell service worker `public/sw.js`: precache shell, network-first для navigations,
  cache-first для same-origin `/assets/` и `/ort/`; **не** перехватывает `.onnx`
  (кэш весов остаётся в приложении, Р-17).
- При отдаче HTML из SW снова выставляются COOP/COEP (Р-08), иначе offline shell
  потерял бы `crossOriginIsolated`.
- Регистрация только в production web (`register-sw.ts`); в dev HMR не трогаем.
- Из пакета расширения `manifest.webmanifest` / `sw.js` вычищаются post-build —
  это не MV3 background.

Ограничение: установленная PWA не даёт context menu / action icon; для этого по-прежнему
нужно расширение. Первый запуск с весами по-прежнему требует сеть.
